Bootstrapping: a practice world first

On day one, the AI has never met a learner. So we build a practice world, test the AI in it, then bring in real people, starting small.

More detail
  • The lesson is stored as data the code understands: question, right answer, trap, off-topic.
  • A big AI model writes new versions on other topics (refunds, leave, shipping).
  • Code rejects any version where the trap is not really wrong, or the right answer is not really right.
  • Result: hundreds of checked lessons, all with the same shape, so every trap means the same thing.

2 · Fake students

Each fake student is a small program with one habit. It picks, reacts to the tutor, and sometimes forgets. Click one to watch it.
Pick a fake student above.
More detail
  • Habit: what it tends to pick (e.g. the look-alike 80% of the time).
  • Reaction: how it changes after each tutor move (e.g. "dates side by side" fixes the look-alike habit 6 times in 10, a plain "wrong" only 2 in 10).
  • Noise: slow answers, misclicks, leaving halfway, forgetting by day 3.
  • Words: an AI writes its chat questions only. It never decides the picks, because AI-played students tend to fix their own mistakes.

3 · Test the AI before anyone sees it

Every new version of the AI must pass these checks on the fake students. Like a driving test.
The habit numbers come from the lesson's fake-student run (200 bots). The other four results are examples of what the checks would report.
More detail
  • Checks run on every change, like software tests.
  • Later, the same checks also run on saved real sessions. Because every move was logged with its odds, we can estimate how a new AI would have done.
  • Passing here only means "not broken". It does not prove people learn. Only step 4 does.

More detail
  • Recruit through a paid panel (e.g. Prolific), people new to RAG.

  • People who don't come back are counted as missing, not as a pass.
